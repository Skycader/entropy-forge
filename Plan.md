# ENTROPY_FORGE — план

Учебный проект: от «случайности из рисунка» к базовым инструментам криптографии.
Всё работает в браузере, без сервера, в том числе по `file://`.

## 1. Рандомайзер ✅

Есть сейчас:
- источники энтропии: рисунок, текст;
- хеш-функции на выбор: DJB2 / MD5 / SHA-256;
- генераторы на выбор: LCG / SFC32;
- соль (unix timestamp или вручную), воспроизводимый результат;
- `randInt`, `double`, `randomString`, лог, оценка стойкости.

## 2. Генератор пар ключей RSA

- Размер ключа на выбор: 1024 (только для обучения) / 2048 / 3072 / 4096.
- Экспорт ключей: PEM (`-----BEGIN PUBLIC KEY-----`), JWK; копирование и скачивание файлом.
- Импорт своих ключей (PEM / JWK).
- Показ «внутренностей» ключа: `n`, `e`, `d`, `p`, `q` — в духе подсказок с формулами (как у LCG).

## 3. Шифрование и расшифрование

- **Текст:** RSA-OAEP напрямую — подходит только для коротких сообщений (до ~190 байт при 2048 бит).
- **Файлы и длинный текст:** гибридная схема — случайный ключ AES-GCM шифрует данные, RSA-OAEP шифрует этот ключ.
- Формат результата: base64 для текста, отдельный файл для файлов (заголовок + зашифрованный ключ + IV + данные).
- Расшифрование приватным ключом; понятная ошибка при неверном ключе или повреждённых данных.

## 4. Подписи сообщений и файлов

- Подпись приватным ключом: RSA-PSS (по умолчанию) или RSASSA-PKCS1-v1_5.
- Проверка подписи публичным ключом: «подпись верна / неверна».
- Подпись файла — от его SHA-256; подпись хранится отдельно (`.sig`) или рядом в base64.

## Ключевое решение: откуда случайность для ключей

Генератор этого проекта (рисунок → хеш → LCG/SFC32) **не криптостойкий**: LCG и SFC32
предсказуемы, а энтропия ограничена 32–128 битами. Ключи RSA из него будут учебными, но не надёжными.

Варианты:
1. **Учебный режим** — RSA «с нуля» на `BigInt` (поиск простых чисел, Миллер — Рабин, `e = 65537`),
   случайность — из нашего генератора. Наглядно: видно, как ключ зависит от рисунка и соли,
   можно воспроизвести тот же ключ. С явной пометкой «не для реального использования».
2. **Надёжный режим** — WebCrypto (`crypto.subtle.generateKey`, RSA-OAEP / RSA-PSS):
   ключи от системного криптостойкого генератора, рисунок на них не влияет.
3. **Оба режима** с переключателем — по аналогии с выбором хеша и генератора.

Склоняюсь к варианту 3: учебный режим показывает, как всё устроено, надёжный — как это делают на практике.

## Открытые вопросы

- Как встроить в интерфейс: новые вкладки рядом с «рисунок / текст» или отдельная правая панель «KEYS / CRYPT / SIGN»?
- Хранить ли ключи между сессиями (localStorage) или только в памяти до перезагрузки?
- Нужна ли совместимость с OpenSSL (проверять подписи и расшифровывать нашими ключами снаружи)?
- Ограничение размера файлов (всё считается в браузере, в памяти).
